# 向量数据库选型与调优

向量数据库负责存 chunk 向量并做近似最近邻搜索。数据量在几十万以内时，单机 FAISS 的暴力检索精度最高、运维成本最低；数据量上千万或需要在线增删时，再考虑 HNSW 索引或 Milvus、Qdrant 等服务。调优抓三个旋钮。第一是向量维度与归一化，余弦相似度要求向量先做 L2 归一化，否则长短文本的分数不可比。第二是索引参数，HNSW 的 ef_construction 决定建索引质量，ef_search 决定查询精度与延迟的 tradeoff，上线前要压测出拐点。第三是混合检索，纯向量检索对生僻新词和精确实体经常翻车，线上系统一般向量加关键词做加权融合。选型结论一句话：先暴力后近似，先单机后服务，用评测数据说话。
